# Testing strategy

```bash
PYTHONPATH=src python3 -m pytest -q
cd frontend && npm run lint && npm run build
```

| Suite | What it checks |
|---|---|
| `tests/unit/test_algorithms.py` | Topology shapes, baseline paths, link failure, capacity/latency behavior and runtime reset, Q-learning versioning and checksums. |
| `tests/unit/test_persistence.py` | State round-trips through the SQL adapter, namespace isolation, redacted URLs. |
| `tests/integration/test_api.py` | Untrained RL is refused; training; identical results for repeated comparisons on the same seed; packet accounting; failure and recovery; experiment history; `lab/latest` follows retraining and topology rebuilds. |
| `tests/integration/test_persistence_restart.py` | Experiments written by one process are served by a fresh one (set `PERSISTENCE_TEST_DATABASE_URL` for PostgreSQL). |

Browser checks for the portfolio build live in the repository's `tools/verify_frontend_workflows.mjs` (run demo, four comparison rows, link failure).

All inputs are generated by the simulator from fixed seeds; there is no external data.
